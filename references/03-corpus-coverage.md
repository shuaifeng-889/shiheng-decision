# 案例库覆盖面审计（扩库前必读）

> 这份文档记录一次真实审计的结论。**扩库前先读它**，否则很容易把案例加到
> 已经过剩的维度上，而真正的盲区一动不动。

审计基线：50 条（2026-10-24 扩容前）
当前规模：64 条（扩容后）

---

## 一、审计方法

不靠感觉，按四个可量化维度切：

1. **时代分布**——按大时段归并（春秋 / 战国 / 秦末汉初 / 两汉 / 三国 / 两晋南北朝 /
   隋唐 / 五代十国 / 宋 / 辽金元 / 明）
2. **对抗原型分布**——`archetype` 字段取值计数
3. **11 维 SV 标签分布**——看哪些取值从来没出现过
4. **主题域覆盖**——按关键词粗筛（军事 / 政治 / 外交 / 商业 / 组织 / 个人）
5. **孤立度**——每条案例与库内其他案例的最高相似度，找「扎堆」与「孤独」

再加一个「现代高频场景」清单，直接检验用户实际会问的问题有没有对应案例。

---

## 二、审计结论（50 条基线）

### 盲区 A：三个原型零覆盖

| 原型 | 条数 |
|---|---|
| STACKELBERG | 17 |
| SIGNALING | 13 |
| COALITION | 6 |
| REPEATED | 6 |
| CHICKEN | 5 |
| STAG_HUNT | 3 |
| **PRISONERS_DILEMMA** | **0** |
| **DEADLOCK** | **0** |
| **BOXED_PIGS** | **0** |

囚徒困境和死锁是现代最高频的两种结构（价格战、竞标、军备竞赛、双输诉讼），
案例库里却一条都没有。这意味着 L2 判定为 PD 时，L1 拿不出任何同构史案，
报告会出现「数学结论很硬、史案对标答非所问」的撕裂。

### 盲区 B：`stakes` 严重偏斜

| 取值 | 条数 |
|---|---|
| existential | 40 |
| high | 9 |
| medium | 1 |
| **low** | **0** |

这是最要命的一条。用户问「要不要接这个 offer」「怎么谈加薪」时，
SV 的 `stakes=low/medium`，而库里 80% 是生死存亡。
相似度会被拉低但结构完全不对——这正是「回复内容不符合决策处境」的主要来源。

**但这是来源决定的，不是缺陷**：正史只详细记录国家级存亡决策，
日常尺度的决策在史书中不留痕。所以扩库只能缓解，不能根治。
根治手段是 SKILL.md 的「史案匹配度」机制——如实降级，而不是硬拔高匹配度。

### 盲区 C：主题域单一

军事-战场指挥 **42/50（84%）**；商业-贸易经营 2；组织-制度改革 **0**；
个人-仕途抉择 0。

### 盲区 D：时代偏斜

宋 2 + 辽金元 2 + 明 1 + 五代十国 1 = **6 条**。
而近世（宋元明清）的制度形态——官僚、科举、财政、商业行会——
恰恰最接近现代组织，案例却最少。

### 盲区 E：现代高频场景

跳槽/择业 0、与上级冲突 0、婚恋 0、财产分配 0、诉讼 0、舆论公关 0。

扩容前首推是生死存亡级的史案；扩容后**首推「田忌赛马」**——
赌注量级对了，结构（资源对等时的排序决策）也对了。

## 四、仍未解决的（诚实清单）

1. **`BOXED_PIGS` 仍是 0 条**。智猪结构（大猪主动、小猪等待）在正史中难见纯例，
   不建议硬凑。若需用到，主要结论应来自 L2 数学求解。
2. **`stakes=existential` 仍占 45/64（70%）**。这是来源性质决定的，
   扩库无法根治，只能靠「史案匹配度」机制如实降级。
3. **军事成分仍占 81%**。同上。
4. **宋元明清仍只有 6 条**。
5. **现代场景（跳槽、婚恋、诉讼、舆论）仍为 0**。这些在正史中本就不存在对应物，
   强行映射属于时代错置。正确做法是明确告知用户「这类处境史书不留痕」，
   然后只提供结构框架，不提供史案类比。

## 五、扩库操作规范

新增案例必须同时满足：

1. **T1 正史确载**——书名、篇目可检核，不接受演义系统（《三国演义》等 T3）
2. **17 个字段齐全**——见 `tests/test_corpus.py` 的 `req` 元组
3. **`sources` 结构化**——`{book, juan, canonical, category}`，`book` 须属二十四史
4. **`sv_tags` 11 维齐全**，取值须在 schema 取值域内
5. **双向索引回写**——新案例要加入至少一条兵计的 `case_ids`，
   否则 `test_corpus.py` 的「孤立史案为 0」会失败
6. **先审计再动手**——照第一至四节的方法跑一遍，确认加的是真盲区

来源有瑕疵但不属演义系统的（如 C058 子贡，太史公叙事有策士自神其术倾向），
用 `evidence_warning` 字段显式标注，不要悄悄当确证用。
