# 06 · 标定权重与接入 Agent

**目标**：把模型调成你所在领域的形状，并封装成自己的 Skill。

---

## 权重是怎么起作用的

检索不是关键词匹配，是**加权欧氏距离**：

```
distance = sqrt( Σ w_i × (sv_i − case_i)²  / Σ w_i )
similarity = 1 − distance / MAX_DIST
```

`w_i` 就是 `WEIGHTS` 里那个数字。它表达的是：**"这一维判断错了，对结论的伤害有多大"**。

当前的值（`scripts/engine.py`）：

| 维度 | 权重 | 取值理由（原注释） |
|---|---|---|
| `power_ratio` | **3.0** | 强弱对比决定攻守的基本取向 |
| `reversibility` | **2.5** | 不可逆性决定能否用一次性激烈手段 |
| `horizon` | **2.5** | 单次/重复决定信誉是否计息，影响最大 |
| `stakes` | 2.0 | 赌注决定可接受的风险敞口 |
| `info_asym` | 2.0 | 信息差是所有信号的燃料 |
| `actors` | 2.0 | 参与方数决定是否需要考虑第三方 |
| `opponent_rationality` | 2.0 | 对手类型决定信号能否被解读 |
| `moral_constraint` | 2.0 | 红线约束，直接参与风险折扣 |
| `time_pressure` | 1.5 | 时间压力压制谋略空间 |
| `third_party` | 1.5 | 可借力对象的有无 |
| `resource_slack` | 1.5 | 冗余决定能否打持久消耗 |

**这组数字是先验设定，不是学习得到的。** 它是设计判断，不是事实。所以它可改，也应该按领域改。

---

## 改之前先知道哪个最敏感

我做过一组扰动实验：三个结构迥异的场景，只改一个权重，看首推策略会不会变。

| 改动 | 三场景首推 | 结论 |
|---|---|---|
| 基准 | 借刀杀人 / 关门捉贼 / 打草惊蛇 | — |
| `power_ratio` 3.0 → 6.0 | 借刀杀人 / 关门捉贼 / 打草惊蛇 | **完全不变** |
| `horizon` 2.5 → 5.0 | **远交近攻** / 关门捉贼 / **假痴不癫** | **两个变了** |
| `moral_constraint` 2.0 → 4.0 | 借刀杀人 / 关门捉贼 / 打草惊蛇 | 完全不变 |

三个发现：

1. **`power_ratio` 加倍不影响结论。** 说明它已经在多数处境的极端位置（要么很弱要么不弱），
   再加重也没用。如果你想让强弱对比更主导，得**降低**其他维度，而不是继续抬高它。
2. **`horizon` 是最敏感的开关。** 它一改，结论就翻转。这也解释了为什么在
   [教程 03](03-encoding.md) 里说它是"被低估得最严重的一维"。
3. **`moral_constraint` 对排序几乎无影响**，因为它是通过**风险折扣**间接起作用的，
   不是通过相似度。要调道德约束的实际影响力，改 `moral_floor` 参数比改权重有效。

**结论：改权重时优先动 `horizon`，其次 `reversibility`，别在 `power_ratio` 上使劲。**

## 三个领域特化方案

### 职场 / 组织内决策

组织内博弈的特点：长期共处（`repeated` 几乎恒成立）、可逆性低（一句错话收不回）、
对手是理性的但受组织规则约束。

```python
WEIGHTS = {
    "power_ratio": 2.5,        # 组织内职级差距没有看上去那么决定性
    "stakes":      2.0,
    "reversibility": 3.5,      # 上调：组织内的言行不可逆性极高
    "info_asym":   2.5,        # 上调：信息差是组织内最主要的资源
    "time_pressure": 1.5,
    "horizon":     3.5,        # 上调：几乎永远是重复博弈
    "actors":      2.5,        # 上调：组织里总有第三方（上级、同僚、HR）
    "third_party": 2.0,
    "resource_slack": 1.5,
    "opponent_rationality": 2.5,  # 上调：误判对手是否理性代价极大
    "moral_constraint": 2.0,
}
```

### 商业谈判 / 供应商与客户

特点：赌注高、可逆性中等、对手理性、有明确的收益表可填。

```python
WEIGHTS = {
    "power_ratio": 3.5,        # 上调：谈判里实力对比几乎决定一切
    "stakes":      2.5,        # 上调：单笔金额与后续影响
    "reversibility": 2.5,
    "info_asym":   3.0,        # 上调：谈判本质是信息博弈
    "time_pressure": 2.5,      # 上调：谁的时间更紧谁先让步
    "horizon":     2.5,
    "actors":      2.0,
    "third_party": 2.0,
    "resource_slack": 2.0,     # 上调：能不能拖
    "opponent_rationality": 2.0,
    "moral_constraint": 1.5,   # 下调：商业场景的合规边界比人际场景清晰
}
```

### 个人重大选择（换城市、读不读、走不走）

特点：几乎没有"对手"，但有多个目标函数在竞争；可逆性差异极大；信息严重不足。

```python
WEIGHTS = {
    "power_ratio": 1.0,        # 大幅下调：没有真正的对手，这维几乎无用
    "stakes":      3.0,        # 上调：赌注是核心
    "reversibility": 4.0,      # 上调：能不能回头是最重要的
    "info_asym":   2.0,
    "time_pressure": 2.0,
    "horizon":     3.5,        # 上调：影响年限
    "actors":      1.0,        # 下调：通常是自己与自己
    "third_party": 1.5,
    "resource_slack": 2.5,     # 上调：还有多少试错空间
    "opponent_rationality": 0.5,  # 大幅下调：无对手
    "moral_constraint": 2.0,
}
```

注意最后两个方案里我把 `power_ratio` 和 `opponent_rationality` 压到 1.0 以下。
**这是关键：领域特化不只是"调高重要的"，更是"调低不存在的"。**
一个不存在的维度如果还占 2.0 权重，它会持续把检索往错误的方向拉。

## 改完之后必须做的验证

```bash
python tests/test_discrimination.py
```

这个测试要求**三个结构迥异的场景必须推出三条不同策略**：

```
囚徒困境场景 → 借刀杀人
死锁场景     → 趁火打劫
猎鹿场景     → 指桑骂槐
```

如果你的新权重让三个场景推出了同一条策略，说明权重压塌了判别力——
模型退化成"什么情况都推荐同一计"。**这时候必须回退。**

改完还要跑：

```bash
python scripts/cli.py validate       # 数据没被破坏
python tests/test_cli.py            # 命令行没被破坏
```

## 加新维度的风险

有人会想加第 12、13 维（比如"情绪状态"、"身体状态"）。可以做，但要动三处：

1. `WEIGHTS` 加键
2. `ORDINAL` 加取值映射（如果是枚举型）
3. `data/cases.json` 的 `meta.sv_legend` 加说明
4. **`data/cases.json` 里 50 条案例的 `sv_tags` 全部补上这一维**

第 4 步是真正的成本。`test_corpus.py` 有一条断言：

```python
check("sv_tags 维度与 meta 一致",
      len([c["id"] for c in cases if set(c["sv_tags"]) != keys]), 0)
```

维度不一致会直接挂。而且新维度如果没有历史案例支撑，它在相似度计算里起的是**噪声**作用，
不是信息作用。

**建议：先不加维度。** 如果某个因素确实重要，用现有维度近似（"情绪状态差"可以表达为
`opponent_rationality=vindictive` 或 `info_asym` 为负），或者写进 `failure_if` 里。

## 接入 Agent：SKILL.md 怎么写

`SKILL.md` 是给 AI Agent 读的执行协议。它有两种读者：**Agent** 和**用户**。

### frontmatter 决定何时被触发

```yaml
---
name: shiheng-decision
description: "史衡·五链决策模型。把博弈论与正史案例打通，为现实决策提供可验证的
  个性化参考。触发场景：用户提出两难/多选/竞争/谈判/组织人事/重大取舍类问题，
  或明确提到史书典故、兵法策略、博弈论、决策分析。"
---
```

`description` 是**唯一的触发机制**，要写清两件事：

1. **这个 skill 做什么**（一句话）
2. **什么情况下该用**（具体场景词 + 用户可能说的原话）

写坏的例子：

```yaml
description: "一个很强大的决策工具"     # 没有触发词，永远不会被选中
```

写好的例子：

```yaml
description: "...触发场景：两难、取舍、谈判、竞争、跳槽、组织人事、重大投入；
  用户提到史书、兵法、博弈论、决策分析时也适用。"
```

### 正文要有强制纪律，不能只有建议

这是这个 skill 和其他 skill 最大的区别。看 `SKILL.md` 的「核心纪律」：

```markdown
1. 史料分级不可跳过
2. 失效条件优先于成功故事
3. 必须给出反事实
4. 影子谏官不可省略
5. 不宣扬阴谋诡计
```

**写"必须"而不是"建议"。** Agent 读到模糊指令会自由发挥，读到硬约束才会照做。

### 把脚本调用方式写死

不要让 Agent 自己猜怎么调：

```markdown
### L1 RETRIEVE

```bash
cd <skill_dir>/scripts
python engine.py --demo
```
```

或者给它一个确定的 CLI 命令。**Agent 猜 API 的失败率很高。**

## 做成你自己的领域特化 Skill

一个完整的定制流程：

1. **复制整个目录**，改名（比如 `shiheng-hr-decision`）
2. **改 `WEIGHTS`** 按上面三个方案之一调
3. **补你领域的案例**——这是真正的工作量。HR 场景要补组织人事类史案
   （C032 穰苴斩庄贾、C043 魏征纳谏都是现成的）
4. **改 `SKILL.md` 的 description**，把触发词换到你领域的说法
5. **改报告结构的语言要求**——如果给专业人士用，可以放宽"说人话"这一条
6. **跑全套测试**，确认没退化成恒推一计

**最重要的一条：不要改掉「失效条件优先」和「影子谏官」。**

这两条是这个项目区别于普通"AI 建议生成器"的全部理由。去掉它们，
它就退回到一个会说漂亮话的算命工具。

## 最后

这个项目的所有设计都指向一个判断：

> **决策工具的价值不在于给出答案，而在于让你看见自己漏掉的那一维。**

权重可以调，案例可以加，领域可以换。但「失效条件优先」和「强制反驳自己」这两条不能丢——
它们是这套东西成立的地基。
